## Normative rules

1. **Identity and dimensions.** A case is bound to task ID, exact original claim and supplied context; new run IDs cannot renew its call allowance. Positions retain run/position IDs, raw response and hash, provenance, evidence and Phase8-derived assessment. Compare raw label only with raw label, derived taxonomy only with derived taxonomy, and scientific state only with scientific state. A Phase8 ceiling within one position is not a disagreement. Small conflict categories: label, evidence, proposition, causal strength, product transfer, search scope, composite and unknown. IDs and ordering are deterministic.
2. **Materiality.** Confidence and explanatory wording alone are trivial. A difference is material when it changes composite state, admissible output, a proposition influencing that state, a claim-bound population/endpoint/causal/product attribute, evidence direction/selection for that proposition, a material transformation or mandatory control. Optional unknown components that cannot alter composite/output do not automatically demand human review. Missing/mismatched proposition identities cannot be silently aligned by list order. Retain all positions; no voting or history deletion.
3. **Routing.** AUTO_RESOLVABLE means no additional adjudication is required, never support or release. Valid stable positive AND negative cases qualify. Concrete material unknown/fragility requires one countercheck (REVIEW_RECOMMENDED, mandatory=true); nonmaterial uncertainties can remain optional. Actual material opposing positions and critical failed source/completeness/mandatory controls require HUMAN_REVIEW_REQUIRED. Missing authorization/budget/reviewer or failed mandatory execution is UNRESOLVED, with distinct not_executed/failed/completed execution status. Reviewer agreement cannot clear existing material conflict. Human adjudication can resolve a conflict only through an explicitly selected or corrected, revalidated position; unknown and failed controls remain visible.
4. **Triggers.** Every trigger cites affected claim/proposition, field and/or evidence: verdict conflict, evidence direction, necessary unknown, population/endpoint/causality/product mismatch, material transformation, critical source binding, inadequate strong-absence search or failed mandatory control. No trigger from confidence or a generic problem checklist. Technical incomplete extraction is distinct from scientific unknown.
5. **Review.** One thin adapter calls the existing runner/parser with a registered review prompt variant. Initial challenge includes exact original claim/context, all bound evidence IDs/source IDs/quotes and proposition IDs/spans. Exclude first label, conclusion, confidence, gold, evidence direction and interpretive rationale from the challenge. Record shared extraction/source/model limitations; blindness is not independent scientific replication. Runtime execution in this task accepts only the built-in recorded offline provider, never live providers. No hidden retries.
6. **Adjudication and persistence.** Original, counterreview, stability and final derived layers remain separate. Each decision has ID, case/run/position/claim/proposition references, conflict type, original positions, reason, evidence, actor type/provenance, outcome, timestamp and code/contract version. Only an explicit host human-submission API can create actor=human; model text never can. A corrected raw analysis is a new version linked to its parent, validated against the same original task through Phase8. Mandatory controls cannot be waived. Persist with existing RunRecord metadata, decision log and local atomic JSON; no service/database. Replay/render are read-only and cannot execute calls or invent adjudication. Historical records without Phase9 explicitly show not_executed.
7. **Stability.** Only materially uncertain/fragile cases qualify. The sole permitted variant reverses the complete evidence packet ordering without changing claim, context, proposition identities/spans, sources or bindings. Validate canonical content equality; reject any other change with recorded reason. At most one variant/attempt per case, not per proposition. Record a material flip as a conflict; never choose the preferred result. A no-op or invalid variant is recorded, not resampled.
8. **Governance.** Default offline authorization allows zero calls. A host grant allows at most one counterreview and one eligible stability attempt for the bound case. Use existing BudgetLedger with explicit policy while preserving legacy defaults. Reserve durably before entering the provider boundary; begun/failed attempts consume allowance. Case storage lease prevents concurrent races. Reopening/replaying a case, new run IDs, failed calls and missing results cannot reset caps. Historical ledgers are never used. Stable simple cases use zero additional calls. Denied execution remains visible and is not successful review.
9. **Integration and completion.** The actual runner/evaluator/library/report path carries separate Phase8 scientific/taxonomy and Phase9 review/execution status. Rendering revalidates without execution. PHASE_9_PASS requires 9.1–9.10 code evidence, valid and failing controls, frozen offline acceptance, required checks and no unresolved material critic findings. Fixtures establish implementation consistency only, not accuracy, reviewer quality or general safety.

## Validation and bounded review

Development regressions are separate from a small generic acceptance corpus. Freeze corpus version, expectations and SHA256 before acceptance execution; no holdout claims. One contract review before implementation; each WP one initial critic review and at most two targeted correction/rechecks. Unresolved material findings after that yield PARTIAL/BLOCKED. Final report review checks evidence only. One full suite after integration; repeat only after relevant changes/failures. Contract corrections require a version, reason and affected revalidation. Exactly three task documents: this contract/matrix, journal and closeout.
